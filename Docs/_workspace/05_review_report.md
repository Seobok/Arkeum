## 종합 평가
- 개발 준비 상태: 수정 후 진행 가능
- 총평:
  - 새 문서 세트는 `아르케움`을 행동 기록 및 예측 시스템으로 통일했다.
  - 턴제 구조, 예측 표시, 타이밍 개입, 로그라이크 반복, 엔딩 이후 캐릭터 해금이 하나의 서사 규칙으로 연결된다.
  - 이전 방향의 마을 구출/거점 확장 구조는 00~05 문서에서 제거되었고, 반복 인식과 파생 캐릭터 확장 중심으로 재정렬되었다.

## 반영된 핵심 개선

### 1. 던전 정체 통일
- 기존 방향:
  - 던전이 구조 변화와 구출 목표를 가진 모험 공간으로 기능했다.
- 변경 방향:
  - 던전은 모든 행동을 기록하고 미래를 계산하는 시스템이다.
- 효과:
  - 로그라이크 반복 구조와 세계관의 이유가 명확해졌다.
  - 매번 다른 듯 익숙한 던전 생성 규칙이 `기록 재조합`으로 설명된다.

### 2. 예측 시스템의 의미 강화
- 기존 위험:
  - 예측 표시가 단순 전투 편의 기능으로 보일 수 있었다.
- 현재 정리:
  - 예측 표시는 이미 계산된 결과의 출력이다.
  - 플레이어가 예측을 따르거나 거부하는 행동은 수렴도/편차도에 반영된다.
- 효과:
  - UI/전투 시스템과 서사가 직접 연결된다.

### 3. 타이밍 개입의 서사적 위치 확정
- 현재 정리:
  - 타이밍 개입은 운명을 완전히 바꾸는 힘이 아니라 계산된 결과를 미세하게 왜곡하는 변수다.
  - 시스템은 이 변수를 제거하거나 범주화하려 하지만 실패한다.
- 효과:
  - 액션성 있는 입력이 주제인 `선택은 존재하는가`와 연결된다.

### 4. 엔딩 이후 구조 정리
- 현재 정리:
  - 엔딩은 탈출이 아니라 반복 인식과 재진입이다.
  - 플레이어블 캐릭터는 이전 반복에서 파생된 결과값으로 해금된다.
- 효과:
  - 반복 플레이, 캐릭터 해금, 플레이 스타일 축적이 모두 서사 보상으로 기능한다.

## 정합성 매트릭스

| 검증 항목 | 상태 | 비고 |
|---|---|---|
| 세계관과 퀘스트 연결 | 통과 | 기록/예측/수렴/편차 규칙이 MQ-01~MQ-06에 반영됨 |
| 퀘스트와 대사 연결 | 통과 | 각 메인 퀘스트에 대응 장면과 로그 문구가 있음 |
| 대사와 분기 연결 | 통과 | 선택지 의도가 수렴/편차/인식/저항 축으로 연결됨 |
| 엔딩 조건 추적 가능성 | 통과 | AX_* 누적 축과 F_* 플래그로 관리 가능 |
| 캐릭터 해금 정합성 | 통과 | 플레이 스타일 플래그와 파생 개체가 연결됨 |
| 사용자 입력 반영 | 통과 | 핵심 루프, 반복 구조, 캐릭터 확장 모두 반영됨 |

## 발견 사항

### 필수 수정 없음
현재 00~05 문서 내부에서는 큰 설정 충돌이 발견되지 않았다.

### 권장 수정 1. 확장 문서와의 충돌 가능성
- 위치:
  - `_workspace/06_system_specification.md`
  - `_workspace/08_monster_design.md`
  - `_workspace/10_dungeon_map_refactor_requirements.md`
  - `_workspace/11_monster_turn_refactor_requirements.md`
- 문제:
  - 이 문서들은 이전 방향의 용어와 전투/던전 설정을 포함하고 있을 가능성이 높다.
  - 00~05 문서는 새 방향으로 교체되었지만, 확장 문서가 아직 새 전제와 맞지 않을 수 있다.
- 제안:
  - 다음 작업에서 06 시스템 문서를 우선 갱신한다.
  - 특히 `예측 표시`, `타이밍 개입`, `기록 재조합`, `수렴도/편차도`를 시스템 요구사항으로 정리해야 한다.

### 권장 수정 2. 보스/층 구조 상세화 필요
- 문제:
  - 현재 퀘스트 문서는 `수렴층 보스`, `관측자 프로세스`, `기록핵`을 언급하지만 보스별 패턴과 층별 연출은 아직 상세하지 않다.
- 제안:
  - 후속 문서에서 다음 항목을 추가한다.
    - 층별 테마
    - 보스 명칭과 역할
    - 보스별 예측/타이밍/기록 gimmick
    - 층별 로그 텍스트 목록

### 권장 수정 3. 수치 노출 방식 결정 필요
- 문제:
  - 분기 문서에는 `AX_CONVERGENCE`, `AX_DEVIATION`, `AX_AWARENESS` 같은 축이 있지만, 플레이어에게 수치를 직접 보여줄지 여부는 정하지 않았다.
- 제안:
  - 개발 단계에서는 내부 수치로 관리한다.
  - 플레이어에게는 로그 문구, 방 구조 변화, 예측 표시 변화, 관측자 대사로 간접 전달한다.

### 권장 수정 4. 파생 캐릭터 첫 빌드 범위 축소
- 문제:
  - 파생 캐릭터가 5종으로 제안되어 있어 첫 구현 범위가 커질 수 있다.
- 제안:
  - 첫 빌드에서는 3종을 우선 구현한다.
    - 가속 개체
    - 관측 개체
    - 보정 개체
  - 집행 개체와 잔류 개체는 반복 데이터가 충분히 쌓인 뒤 확장해도 된다.

## 분기 경로 시뮬레이션

| 경로 | 주요 선택 | 예상 엔딩 | 해금 |
|---|---|---|---|
| 수렴 경로 | 예측을 따름, 익숙한 경로 반복, 일반 행동 선호 | END-A 수렴된 재진입 | 집행 개체 |
| 저항 경로 | 관측 장치 파괴, 예측 거부, 기록핵 거부 | END-B 저항하는 재진입 | 잔류 개체 |
| 인식 경로 | 로그 조사, 잔향 수집, 기록을 읽고 재진입 | END-C 인식한 재진입 | 관측 개체 |
| 편차 경로 | 다른 선택, 타이밍 개입 성공, 기록을 비틀어 재진입 | END-D 편차의 재진입 | 보정 개체 |
| 속도 경로 | 낮은 턴 수, 빠른 클리어, 조사 최소화 | END-E 빠른 반복 | 가속 개체 |
